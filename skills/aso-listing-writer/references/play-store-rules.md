# Google Play listing limits and metadata rules

Verify against the current Play Console help pages before shipping; limits and policy wording can change.

## Character limits (Google Play)
| Field | Limit |
|---|---|
| App name (title) | 30 |
| Short description | 80 |
| Full description | 4000 |
| What's New (release notes) | 500 |
| Developer name | 50 |

## Apple App Store (if both platforms)
| Field | Limit |
|---|---|
| App name | 30 |
| Subtitle | 30 |
| Keyword field (comma-separated, hidden) | 100 |
| Promotional text | 170 |
| Description | 4000 |

On the App Store, do not repeat words across name, subtitle and keyword field; each word only needs to appear once.

## Metadata policy red flags (Play)
Avoid in title, icon, and developer name:
- Emoji, emoticons, repeated special characters, ALL CAPS words (unless it is the brand)
- Performance/ranking claims: "best", "#1", "top", "No.1"
- Promotional or price words: "free", "sale", "discount", "new", "download now"
- Store-programme words such as "Editor's Choice" unless actually awarded

Avoid in descriptions:
- Keyword stuffing: lists of unrelated terms, or the same word/phrase repeated unnaturally
- Misleading claims about functionality, permissions, or data handling
- Unattributed user testimonials, or references to other apps that imply affiliation
- Excessive or irrelevant formatting and emoji

## Ranking-relevant placement
- Primary keyword: title, short description, first sentence of full description
- Secondary keywords: spread across the full description in natural sentences
- Play indexes the full description; the first lines also decide expansion/conversion

## Measuring
Play Console > Store presence > Store listing experiments lets you A/B test icon, short description, and full description. Change one element at a time and run long enough for a stable result.
